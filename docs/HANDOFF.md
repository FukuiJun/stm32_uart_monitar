# UartMonitor プロジェクト引き継ぎ資料

Claude Codeでの開発再開・仕様書作成のための背景資料です。
このファイルをプロジェクトフォルダに置いた状態でClaude Codeに読み込ませてください。

---

## 1. プロジェクトの背景

- マイコン: **STM32L552VET6**
- マイコンからUART経由でバッテリー関連の測定データ（AD変換値、電圧・電流・SOC/SOHなど）をPCへ送信
- PC側でリアルタイム表示とCSV保存を行うツールとして **UartMonitor** を開発
- 別途、GRAPHTEC GL240というロガー機器のCSVも存在し、将来的にはこの2つのCSVを1つのExcelにまとめるツールをClaude Codeで作る予定（本資料はその前段階として、UartMonitor自体の引き継ぎを目的とする）

### 名称について
PC側ツールの名前は当初「UART Logger」としていたが、GL240（測定器のロガー）と役割が混同されるため、**「UartMonitor」**に変更した。ファイル名は `uart_monitar_gui.py`（スペルはこのまま採用）。

---

## 2. マイコン側の通信仕様

- 通信速度: ボーレート可変（PC側GUIから選択、初期値115200bps）
- 通信頻度: 概ね1秒に1回程度（初期の想定は1秒に10回だったが、現在のフォーマットでは1行1サンプル、間隔はINTERVAL設定に依存）
- 1行1サンプルのカンマ区切りテキスト形式：

```
UP, 27368, V, 3925, I, -90, Cap, 812/1261, SOC, 65, SOH, 94, T, 24.8
```

フィールド意味：

| ラベル | 内容 |
|---|---|
| UP | 固定の行頭マーカー |
| (2番目の値) | マイコン側のミリ秒カウンタ(t_ms) |
| V | 電圧(mV) |
| I | 電流(mA) |
| Cap | 現在容量/最大容量(mAh) |
| SOC | 充電状態(%) |
| SOH | 健全度(%) |
| T | 温度(℃、まれに "24. 8" のように余分な空白が入ることがあるため、パース時に空白除去が必要) |

## 3. PC側ツール（UartMonitor）の現状仕様

**ファイル**: `uart_monitar_gui.py`（Python、customtkinter使用）

### 主な機能
- COMポートを自動検出し、ST-Link/USB Serial等のキーワードからそれらしいポートを自動選択（Intel AMTやBluetoothの仮想ポートは除外）
- ボーレートをプルダウンで選択（GUIラベル: `BAUDRATE(bps)`）
- **INTERVAL(ms)** 入力欄で、CSVの経過時間(`elapsed_ms`)に加算する固定値を指定可能（初期値: 1000）。実時間計測ではなく、行を受信するたびにこの固定値を加算していく方式
- **FILENAME** 入力欄で出力CSVのベース名を指定可能（初期値: `mcu_log`）。接続するたびに `mcu_log1.csv`, `mcu_log2.csv`...と自動的に連番採番される
- 接続/切断は1つのトグルボタンに統合（未接続時は緑「接続」、接続中は赤「切断」、処理中は「接続中...」「切断中...」と表示）
- ログ表示欄はGUI内にリアルタイム表示され、接続するたびにリセットされる
- 直近の電圧・電流・SOCをステータスバーに表示
- バックグラウンドスレッド+キューでシリアル受信し、GUIをブロックしない設計

### CSV出力フォーマット（現状）
ヘッダー行付きの通常の表形式：

```
pc_timestamp, t_ms, elapsed_ms, voltage_mV, current_mA, cap_mAh, cap_max_mAh, soc_percent, soh_percent, temp_C
```

### デザイン
- 「計測機器風」をコンセプトにしたダーク基調のUI（背景 `#0d1117`、パネル `#161b22`）
- アクセントカラーは**緑**（`#22c55e`系）に統一
- 接続中の切断ボタンのみ赤（`#f85149`）で危険操作を強調
- 等幅フォント（Consolas）を全体で使用

### 未確定・今後の検討事項
- GL240側のCSVフォーマットは未共有（今後Claude Codeで統合ツールを作る際に必要）
- 現在のUartMonitorのexe化（PyInstaller）はまだ未実施
- マイコン側の出力フォーマット自体をさらに見直す余地あり（シーケンス番号、チェックサムなどの信頼性向上策は提案済みだが未実装）

## 4. これまでの主な設計判断の経緯（参考）

- 当初はTera Term + Excel VBAでのロギングを検討していたが、Pythonでのロギングに方針転換
- マイコン側の出力フォーマットも「ADCとBATが2行に分かれる形式」→「1行にカンマ区切りでまとめる形式」に変更済み
- GUI化はtkinter→customtkinterに移行し、計測機器風のデザインを採用
- 経過時間の計算方法は「実時間計測」→「ボーレートベースの自動計算」→「INTERVAL欄での手動指定固定値」という順で変遷し、現在は手動指定方式に落ち着いている
